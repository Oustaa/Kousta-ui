Sorting

DataTable supports column sorting for both static (local data) and dynamic (remote) tables. You mark a column as sortable with sortBy, and clicking its header either re-sorts the local data array in place, or calls actions.get with the sort state — merged with whatever pagination/search params are already in play, the same way actions.get already drives pagination and dynamic search.

Which of the two happens is decided purely by whether you pass actions.get — there’s no separate flag to set:

Note No actions.get → sorting a click reorders local data in the browser. actions.get present → sorting a click calls it instead, and nothing reorders locally on its own; your actions.get implementation decides what the new data looks like.

Type definitions: see Props.

Enabling sort on a column

Set sortBy on a header to make it sortable. An empty object is enough:

headers={{
  name: { value: "name", sortBy: {} },
}}

sortBy also accepts two optional fields:

NameTypeDescription
namestringThe key to sort/send instead of the header’s value — for when your display value and your sort/API field differ (for example a nested category.name that your backend expects flattened as category).
sortFunc(a: T, b: T) => numberA custom comparator, used whenever the two cell values being compared aren’t both string or both number — this is what makes exec-based columns (no value to read) sortable, and also covers dates, booleans, or nested objects.
type THeaderSort<T> = {
  name?: string;
  sortFunc?: (a: T, b: T) => number;
};

What happens when you click a sortable header

  • Clicking a column that isn’t currently sorted starts it ascending — always, regardless of what any other column was doing before.
  • Clicking the currently-sorted column toggles its direction (ascending ↔ descending) on every click, not just the first time.
  • Sortable columns show a pair of up/down chevron icons next to the header label; the one matching the active direction is highlighted once that column is sorted, the other stays dim.

Note Default (string/number) comparison only kicks in when both values have the same typeof. Anything else — mismatched types, exec-based columns, dates, nested values — needs sortBy.sortFunc; without it, the click still toggles the header’s arrow and (in dynamic mode) still calls actions.get, but the comparator returns 0 for every pair, so local data won’t visibly reorder.

Static sorting

When you don’t pass actions.get, clicking a sortable header sorts the data array you passed in, right there in the browser.

No actions.get here — clicking a header re-sorts data in place, client-side.

There’s no exposed hook into the static sort itself — DataTable owns data internally once you pass it in, and re-sorts its own copy. If you need to know the current sort state outside the table, static mode doesn’t expose it today.

Dynamic sorting

Pass actions.get — that alone is what switches sorting into dynamic mode. Clicking a sortable header calls it with sortBy (the column’s value, or sortBy.name if set) and direction (1 ascending, -1 descending), merged with the current pagination/search params. Applying the sort — an ORDER BY on your API, or your own logic — is up to your actions.get implementation.

options.sort (custom param names)

If your backend expects different query-param names than sortBy/direction, provide options.sort.props to remap them. This is separate from sortBy.name: sortBy.name changes what value gets sorted/sent, options.sort.props changes the shape of the params object it’s sent in.

props(props: { sortBy: string; direction: number }) => Record<string, string | number>Maps the internal sort state to whatever shape your actions.get handler expects. If omitted, actions.get receives sortBy/direction directly.

Current limitations

Note These are gaps in the current implementation, not just missing docs:

  • There’s no way to read or set the current sort state from outside DataTable in either mode — no controlled sortBy/direction props, and no callback beyond actions.get in dynamic mode.
  • The sort icons aren’t customizable — there’s no config.icons override for them, unlike most other DataTable icons.

# Sorting

`DataTable` supports column sorting for **dynamic** (remote) tables. You mark a column as sortable, and clicking its header calls `actions.get` with the current sort state, merged with whatever pagination/search params are already in play — the same way `actions.get` already drives [pagination](./Pagination) and [dynamic search](./Search). Actually applying the sort (an `ORDER BY` on your API, or your own sort logic) is up to your `actions.get` implementation.

Type definitions: see [Props](./Props).

## Enabling sort on a column

Set `sortBy: true` on any header that uses `value` (not `exec`) — sort reads the column's `value` as the sort key, so `exec`-based columns can't be marked sortable:

```ts
headers={{
  name: { value: "name", sortBy: true },
}}
```

<Badge color="yellow">Note</Badge> `sortBy` is typed to also accept an object (`{ name?: string }`), but only the boolean `true` has any effect in the current implementation — use `true`.

## What happens when you click a sortable header

- Clicking a column that isn't currently sorted starts it ascending.
- Clicking the currently-sorted column again toggles its direction (ascending ↔ descending).
- The header shows a small ascending/descending indicator next to sortable columns, highlighting whichever direction is active.
- If `actions.get` is provided, it's called with `sortBy` (the column's `value`) and `direction` (`1` for ascending, `-1` for descending), merged with the current pagination/search params — unless you override the shape with `options.sort.props` (see below).

## `options.sort` / `config.sort` (custom param names)

If your backend expects different query-param names than `sortBy`/`direction`, provide `props` to remap them. Either `options.sort.props` or `config.sort.props` works — `options.sort.props` wins if both are set.

| Name | Type | Description |
|------|------|-------------|
| `props` | `(props: { sortBy: string; direction: number }) => Record<string, string \| number>` | Maps the internal sort state to whatever shape your `actions.get` handler expects. If omitted, `actions.get` receives `sortBy`/`direction` directly. |

## Current limitations

<Badge color="yellow">Note</Badge> Sorting is wired up for dynamic tables only right now.

- **Static tables** (`isStatic: true`, no `actions.get`): clicking a sortable header still updates the ascending/descending indicator, but the local `data` array isn't reordered — static sorting isn't implemented yet. There's also no exposed callback to hook into the click yourself for static tables today, so you can't work around this from outside the component either. If you need sorted local data right now, sort `data` yourself (for example, from your own "sort by" UI) before passing it to `DataTable`, independently of `sortBy`.
- `sortBy` requires a `value`-based header; `exec`-based columns can't be marked sortable.

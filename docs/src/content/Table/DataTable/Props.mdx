# Props

This page describes what every `DataTable` prop is for, alongside the TypeScript
type definitions used across the DataTable documentation (source of truth:
`packages/table/src/DataTable/_props.ts`).

## `TableProps<T>`

The top-level props accepted by `DataTable`.

| Name | Type | Description |
|------|------|-------------|
| `data` | `T[]` | Rows to display. |
| `loading` | `boolean` | Shows the table loading UI. |
| `title` | `string` | Table title shown in the header. Later it will also be used to fetch table config from local storage (when implemented). |
| `headers` | [`THeader<T>`](#theadert) | Column definitions (label -> how to read/render each cell). |
| `keyExtractor` | `(row: T) => string \| number` | Stable key for each row. |
| `pagination` | [`TablePagination`](#tablepagination) | Enables pagination — see [Pagination](./Pagination). |
| `actions` | [`TActions<T>`](#tactionst) | Row actions, remote fetching, and search — see [Actions](./Actions) and [Search](./Search). Passing `actions.get` is also what switches sortable headers over to calling it instead of sorting `data` locally, see [Sorting](./Sorting). |
| `options` | [`TOptions<T>`](#toptionst) | Extra row actions, bulk actions, views, and select filters — see [Actions](./Actions) and [Views](./Views). |
| `config` | [`TConfig`](#tconfig) | Behavior and element-prop customization — see [Config](./Config). |

```ts
export type TableProps<T> = {
  data: T[];
  loading: boolean;
  title: string;
  headers: THeader<T>;
  keyExtractor?: (row: T) => string | number;
  pagination?: TablePagination;
  actions?: TActions<T>;
  options?: TOptions<T>;
  config?: TConfig;
};
```

---

## `THeader<T>`

`headers` is a map from column label to a [`THeaderValue<T>`](#theadervaluet) definition of how to read or render that column's cells.

```ts
export type THeader<T> = Record<string, THeaderValue<T>>;
```

---

## `THeaderValue<T>`

| Name | Type | Description |
|------|------|-------------|
| `value` | `string` | A key on your row object to read the cell value from. Mutually exclusive with `exec`. |
| `exec` | `(row: T) => string \| ReactNode` | Compute the cell content instead of reading `value`. Mutually exclusive with `value`. |
| `visible` | `boolean` | Whether the column is currently shown. Controlled by the column show/hide ("S/H") menu. |
| `canSee` | `boolean` | Whether the column can be toggled at all in the "S/H" menu. |
| `alwaysVisible` | `boolean` | Keeps the column visible regardless of the "S/H" menu state. |
| `sortBy` | [`THeaderSort<T>`](#theadersortt) | Marks the column sortable — see [Sorting](./Sorting). An empty object (`{}`) is enough to enable it; `name` and `sortFunc` are both optional. Works with `exec`-based columns too, as long as `sortFunc` is provided. |
| `total` | `boolean \| { name?: string; func?: (prev: number, current: number) => number }` | Adds this column to the totals row at the bottom of the table body — see [Total](./Total). `true` or `{}` sums the column's `value` across every currently-displayed row. |
| `filterBy` | [`TableHeaderFilter`](#tableheaderfilter) | Gives the column a row in the filter panel — see [Filtering](./Filtering). `type` is the only required field; it decides both the operator list and the value control. Needs a `value` to read, so it does nothing on an `exec`-only column. |

```ts
export type THeaderValue<T> = {
  value?: string | never;
  exec?: never | ((row: T) => string | ReactNode);
  visible?: boolean;
  canSee?: boolean;
  alwaysVisible?: boolean;
  sortBy?: THeaderSort<T>;
  filterBy?: TableHeaderFilter;
  total?:
    | boolean
    | {
        name?: string;
        func?: (prev: number, current: number) => number;
      };
} & (
  | {
      value: string;
      exec?: never;
    }
  | {
      value?: never;
      exec: (row: T) => string | ReactNode;
    }
);
```

### `THeaderSort<T>`

| Name | Type | Description |
|------|------|-------------|
| `name` | `string` | The key to sort/send instead of the header's `value` — see [Sorting](./Sorting#enabling-sort-on-a-column). |
| `sortFunc` | `(a: T, b: T) => number` | Custom comparator, used whenever the two values being compared aren't both `string` or both `number` — the mechanism that makes `exec`-based columns sortable. |

```ts
type THeaderSort<T> = {
  name?: string;
  sortFunc?: (a: T, b: T) => number;
};
```

### `TableHeaderFilter`

| Name | Type | Description |
|------|------|-------------|
| `type` | `"string" \| "number" \| "select"` | Picks the operator list and the value control — see [Operators by type](./Filtering#operators-by-type). Required. |
| `options` | `THF[]` | The choices for a `select` filter. Required when `type` is `"select"`, and not allowed on the other two. |
| `getOption` | `(item: THF) => { label: string; value: string \| number }` | Maps one of your option objects onto what the control shows and stores. Without it the control reads `value` (falling back to `id`) and `label`. |

```ts
export type TableHeaderFilter<
  THF extends { label: string; value: string | number } = any,
> = {
  type: FilterType;
  options?: THF[] | never;
  getOption?:
    | never
    | ((item: THF) => { label: string; value: string | number });
} & (
  | {
      type: "select";
      options: THF[];
      getOption?: (item: THF) => { label: string; value: string | number };
    }
  | {
      type: "string" | "number";
      options?: never;
      getOption?: never;
    }
);
```

### `total` object shape

Unlike `sortBy`, this isn't a separately-named type in `_props.ts` — it's declared inline on `THeaderValue<T>`, shown above. The object form:

| Name | Type | Description |
|------|------|-------------|
| `name` | `string` | The key to read and sum instead of the header's `value` — see [Total](./Total#reading-a-different-field). |
| `func` | `(prev: number, current: number) => number` | Custom reducer called once per row instead of a plain sum. Must return a number — see [Total's current limitations](./Total#current-limitations) for what happens if it doesn't. |

## `TablePagination`

| Name | Type | Description |
|------|------|-------------|
| `total` | `number` | Total number of rows (used for page count and the "Showing X to Y" message). |
| `page` | `number` | Initial page (1-indexed). |
| `limit` | `number` | Initial rows per page. |
| `type` | `"static" \| "dynamic"` | `static` slices `data` client-side. `dynamic` expects you to fetch and update `data` yourself, driven by `actions.get`. |

```ts
type TablePagination = {
  total: number;
  page: number;
  limit: number;
  type?: "static" | "dynamic";
};
```

## `TActions<T>`

| Name | Type | Description |
|------|------|-------------|
| `get` | `(params: TParams) => void` | Fetch table data remotely. Called with `{ page, limit, search }` when pagination/search changes (when configured). |
| `edit` | `{ onEdit(row); canEdit?; title?; buttonProps? }` | Adds an edit action for each row (button + context menu). `afterEdit` exists in the type but isn't implemented yet. |
| `delete` | `{ onDelete(row); canDelete?; title?; buttonProps? }` | Adds a delete action for each row (button + context menu). `afterDelete` exists in the type but isn't implemented yet. |
| `search` | [`TSearch<T>`](#tsearcht) | Configures search behavior — see [Search](./Search). |

```ts
export type TActions<T> = {
  get?: (params: TParams) => void;
  edit?: {
    canEdit?: CanPerformAction<T>;
    onEdit: (row: T) => void;
    title?: string | ReactNode;
    buttonProps?: ButtonProps;
    afterEdit?: TAfterAction; // Not implemented yet
  };
  delete?: {
    canDelete?: CanPerformAction<T>;
    onDelete: (row: T) => void;
    title?: string | ReactNode;
    buttonProps?: ButtonProps;
    afterDelete?: TAfterAction; // Not implemented yet
  };
  search?: TSearch<T>;
};
```

### `TSearch<T>`

| Name | Type | Description |
|------|------|-------------|
| `static` | `boolean` | When `true`, filtering happens on the client via `onSearch(row, { query, reg }) => boolean`. When `false`/omitted, `onSearch(params) => void` is called like `actions.get`. |
| `onSearch` | depends on `static` | The search callback. Its signature switches based on `static` (see above). |
| `searchOnType` | `boolean` | If `true`, triggers search while typing (debounced). If `false`, the user must press Enter or click the search button. |
| `searchTimer` | `number` | Debounce duration in ms when `searchOnType: true`. |

```ts
type TSearch<T> = {
  searchOnType?: boolean;
  searchTimer?: number;
  static?: boolean;
} & (
  | { searchOnType?: false; searchTimer?: never }
  | { searchOnType?: true; searchTimer?: number }
) &
  (
    | {
        static: true;
        onSearch?: (row: T, props: { query: string; reg: RegExp }) => boolean;
      }
    | {
        static?: false | undefined;
        onSearch?: (params: TParams) => void;
      }
  );
```

## `TOptions<T>`

| Name | Type | Description |
|------|------|-------------|
| `extraActions` | [`ExtraActions<T>[]`](#extraactionst) | Additional per-row actions beyond edit/delete. |
| `emptyTable` | `ReactNode` | Content rendered when there's no data. |
| `sort` | [`SortProps`](#sortprops) | Remaps the params sent to `actions.get` when a sortable column is clicked — see [Sorting](./Sorting). |
| `filter` | [`FilterProps`](#filterprops) | Remaps the params sent to `actions.get` when filters are applied, or replaces the fetch entirely — see [Filtering](./Filtering). |
| `props` | `{ set; get? }` | Hands you the table's state on every change (`set`) and asks for it back on mount (`get`), so you can persist it to storage or the URL — see [Props preserving](./PropsPreserving). |
| `cards` | `{ card(props); cardsContainerProps?; menuProps?; loadingIndicator? }` | Enables the built-in card view. `card` receives `{ row, visibleHeaders }` — see [Views](./Views). |
| `viewComp` | `{ Component(row); type?: "modal" \| "extends"; ...modal/expand options }` | Adds a dedicated "view" action that expands the row or opens a modal — see [Actions](./Actions). |
| `bulkActions` | [`TBulkActions<T>[]`](#tbulkactionst) | Enables row selection and bulk actions on the selection. |
| `extraviews` | `Record<string, `[`TExtraView<T>`](#textraviewt)`>` | Adds custom views beyond table/card, keyed by name — see [Views](./Views). |
| `selectFilter` | `Record<string, (row: T, clearAll?) => boolean>` | Adds a "select by filter" menu next to the header checkbox (requires `bulkActions`) — see [Actions](./Actions). |

```ts
export type TOptions<T> = Partial<{
  extraActions: Array<ExtraActions<T>>;
  emptyTable: ReactNode;
  sort: SortProps;
  filter: FilterProps;
  props: {
    set: (
      props: TablePropsInterface & { page: number; limit: number },
      tableTitle: string,
    ) => void;
    get?: null | (() => Partial<TablePropsInterface>);
  };
  cards: {
    card: (props: { row: T; visibleHeaders: string[] }) => JSX.Element;
    cardsContainerProps?: ComponentPropsWithoutRef<"div">;
    menuProps?: Omit<MenuItemProps, "onClick" | "closeMenuOnClick">;
    loadingIndicator?: LoadingIndicator;
  };
  viewComp: {
    Component: (row: T) => ReactNode;
    type?: "modal" | "extends";
    modalOptions?: Omit<ModalProps, "opened" | "onClose" | "modalTrigger">;
    openModalIcon?: ReactNode;
    extendRowIcon?: ReactNode;
    minimizeRowIcon?: ReactNode;
    openButtonProps?: Omit<ButtonProps, "onClick">;
    canView?: CanPerformAction<T>;
  } & (
    | {
        type: "modal";
        modalOptions?: Partial<ModalProps>;
      }
    | {
        type?: "extends";
        modalOptions?: never;
      }
  );
  bulkActions: TBulkActions<T>[];
  extraviews: Record<string, TExtraView<T>>;
  selectFilter: Record<string, (row: T, clearAll?: VoidFunction) => boolean>;
}>;
```

### `ExtraActions<T>`

| Name | Type | Description |
|------|------|-------------|
| `title` | `string \| ReactNode` | Label shown for the action. |
| `onClick` | `(row: T) => void` | Called when the action is triggered. |
| `Icon` | `ReactNode` | Optional icon shown next to the label. |
| `allowed` | [`CanPerformAction<T>`](#canperformactiont) | Whether the action is available for a given row. |

```ts
type ExtraActions<T> = {
  title: string | ReactNode;
  onClick: (row: T) => void;
  Icon?: ReactNode;
  allowed?: CanPerformAction<T>;
};
```

### `TBulkActions<T>`

| Name | Type | Description |
|------|------|-------------|
| `title` | `string` | Label shown for the bulk action. |
| `onClick` | `(rows: T[], clearSelected: VoidFunction) => void \| Promise<unknown>` | Called with the selected rows; call `clearSelected()` to reset the selection afterward. |
| `valueExtractor` | `(rows: T[]) => unknown` | Computes an aggregate value from the selected rows (for example, a sum to display). |
| `buttonProps` | `Omit<ButtonProps, "onClick">` | Props forwarded to the action's button. |
| `canPerformAction` | `boolean` | Whether the bulk action is currently enabled. |

```ts
type TBulkActions<T> = {
  title: string;
  onClick: (rows: T[], clearSelected: VoidFunction) => void | Promise<unknown>;
  valueExtractor?: (rows: T[]) => unknown;
  buttonProps?: Omit<ButtonProps, "onClick">;
  canPerformAction?: boolean;
};
```

### `SortProps`

| Name | Type | Description |
|------|------|-------------|
| `props` | `(props: { sortBy: string; direction: number }) => Record<string, string \| number>` | Maps the internal sort state (`sortBy`/`direction`) to whatever param shape your `actions.get` handler expects — see [Sorting](./Sorting). |

```ts
type SortProps = {
  props: (props: {
    sortBy: string;
    direction: number;
  }) => Record<string, string | number>;
};
```

### `FilterProps`

| Name | Type | Description |
|------|------|-------------|
| `props` | `(filters: `[`TableFilter[]`](#tablefilter)`) => TParams` | Maps the active filters to whatever param shape your `actions.get` expects. Without it they're sent as a JSON string under a single `filters` key — see [Filtering](./Filtering#optionsfilterprops-custom-param-names). |
| `filterFunction` | `(params: TParams) => void` | Called **instead of** `actions.get` when filters are applied. Setting it also stops the table filtering locally. |

```ts
export type FilterProps = {
  props?: (filters: TableFilter[]) => TParams;
  filterFunction?: (params: TParams) => void;
};
```

### `TableFilter`

One applied filter. This is what `options.filter.props` receives, what a JSON `filters` param decodes to, and what `TablePropsInterface.filters` holds.

| Name | Type | Description |
|------|------|-------------|
| `header` | `string` | The header label the filter came from — the key in your `headers` object. |
| `name` | `string` | The column's `value`, i.e. the path the filter reads. |
| `type` | `FilterType` | `"string"`, `"number"` or `"select"`. |
| `operator` | [`FilterOperator`](#filteroperator) | The chosen operator, or the type's default if it was never changed. |
| `value` | `string \| number \| Array<string \| number> \| null` | The value compared against. `undefined` for operators that take none. Values typed into an input arrive as strings. |
| `to` | `string \| number \| null` | The upper bound — set only when `operator` is `"between"`. |

```ts
export type TableFilterDraft = {
  operator?: FilterOperator;
  value?: string | number | Array<string | number> | null;
  to?: string | number | null;
};

export type TableFilter = TableFilterDraft & {
  header: string;
  name: string;
  type: FilterType;
  operator: FilterOperator;
};
```

### `FilterOperator`

```ts
export type StringFilterOperator =
  | "contains"
  | "not-contains"
  | "is"
  | "is-not"
  | "starts-with"
  | "ends-with"
  | "is-empty"
  | "is-not-empty";

export type NumberFilterOperator =
  | "eq"
  | "neq"
  | "gt"
  | "gte"
  | "lt"
  | "lte"
  | "between";

export type SelectFilterOperator =
  | "is"
  | "is-not"
  | "is-any-of"
  | "is-none-of"
  | "is-empty"
  | "is-not-empty";

export type FilterOperator =
  | StringFilterOperator
  | NumberFilterOperator
  | SelectFilterOperator;
```

### `TablePropsInterface`

The table state handed to `options.props.set` and read back from `options.props.get` — see [Props preserving](./PropsPreserving).

| Name | Type | Description |
|------|------|-------------|
| `query` | `string` | The current search term. |
| `sortBy` | `string` | The value (or `sortBy.name`) of the sorted column; `""` when nothing is sorted. |
| `direction` | `-1 \| 1` | `1` ascending, `-1` descending. |
| `displayAs` | `string` | The active view — `"table"`, `"card"`, or an `extraviews` key. |
| `filters` | [`TableFilter[]`](#tablefilter) | The applied filters; `[]` when nothing is filtered — see [Filtering](./Filtering#saving-and-restoring-filters). |

```ts
export type TablePropsInterface = {
  query: string;
  sortBy: string;
  direction: -1 | 1;
  displayAs: string;
  filters: TableFilter[];
};
```

<Badge color="yellow">Note</Badge> `set` also receives `page` and `limit` on top of these, but only on the call that changed them. `get` doesn't restore either — pagination goes back in through the [`pagination`](#tablepagination) prop.

### `TExtraView<T>`

| Name | Type | Description |
|------|------|-------------|
| `View` | `FC<{ data: T[]; visibleHeaders: string[] }>` | The component rendered for this view. |
| `canView` | `boolean` | Whether this view is available. |
| `menuProps` | `Omit<MenuItemProps, "onClick" \| "closeMenuOnClick">` | Props for the menu item used to switch to this view. |
| `loadingIndicator` | [`LoadingIndicator`](#loadingindicator) | Overrides the loading UI for this view. |

```ts
type TExtraView<T> = {
  View: FC<{ data: T[]; visibleHeaders: string[] }>;
  canView?: boolean;
  menuProps?: Omit<MenuItemProps, "onClick" | "closeMenuOnClick">;
  loadingIndicator?: LoadingIndicator;
};
```

## `TConfig`

| Name | Type | Description |
|------|------|-------------|
| `toggleRows` | `boolean` | Enables the column show/hide menu button ("S/H"). |
| `disableContextMenu` | `boolean` | Disables the row right-click context menu. |
| `noHead` | `boolean` | Hides the entire table head section (search, refresh, view switcher, etc.). |
| `emptyRowIcon` | `ReactNode` | Placeholder shown when a row has no actions. |
| `useGetAsRefresh` | `boolean` | When enabled, the refresh button triggers `actions.get`. |
| `loadingIndicator` | [`LoadingIndicator`](#loadingindicator) | Overrides the loading UI for card/extra views. |
| `icons` | `{ toggleRows?; selectRow?; extraViewsTogle?; tableExtraView?; cardExtraView?; refresh?; selectOpened?; selectClosed?; paginationNext?; paginationPrev?; paginationDots? }` | Overrides the icons used by DataTable UI elements — see [Config](./Config#configicons) for what each key controls. |
| `props` | `{ table?; thead?; tbody?; tr?; th?; td? }` | Props forwarded directly to the underlying table elements. |

```ts
export type TConfig = {
  toggleRows?: boolean;
  disableContextMenu?: boolean;
  noHead?: boolean;
  emptyRowIcon?: ReactNode;
  useGetAsRefresh?: boolean;
  loadingIndicator?: LoadingIndicator;
  icons?: {
    toggleRows?: ReactNode;
    selectRow?: ReactNode;
    extraViewsTogle?: ReactNode;
    tableExtraView?: ReactNode;
    cardExtraView?: ReactNode;
    refresh?: ReactNode;
    selectOpened?: ReactNode;
    selectClosed?: ReactNode;
    paginationNext?: ReactNode;

  props?: {

    td?: ComponentPropsWithoutRef<"td">;
    th?: ComponentPropsWithoutRef<"th">;
    tr?: ComponentPropsWithoutRef<"tr">;
  };
};
```

## Supporting types

### `TParams`

The params object passed to `actions.get` and non-static `actions.search.onSearch`.

```ts
export type TParams = Record<string, number | string | undefined>;
```

### `CanPerformAction<T>`

Either a plain boolean, or a function evaluated per-row, used to conditionally enable/disable an action (`canEdit`, `canDelete`, `allowed`, `canView`, etc.).

```ts
export type CanPerformAction<T> = ((row: T) => boolean) | boolean;
```

### `LoadingIndicator`

Renders custom loading content for card/extra views, given the currently visible headers.

```ts
type LoadingIndicator = (props: { visibleHeaders: string[] }) => ReactNode;
```

### `TAfterAction`

Reserved for a future post-edit/post-delete callback. Present in the types but **not implemented yet**.

```ts
type TAfterAction = (props: TParams) => unknown;
```

### `PropsContextType`

The type used by [`TablePropsProvider`](./TablePropsProvider). It's a partial of props/actions/config that the provider can set as defaults for all `DataTable` instances below it.

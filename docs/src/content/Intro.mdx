# Getting started

<DocHeader
  description="Kousta UI is a React component library built around a data table that does the boring parts for you — sorting, search, pagination, filtering and totals — plus the components, hooks and helpers it is built from."

## Install

Every package is independent, so install only what you need. Most people start with the table, which pulls the rest in as dependencies:

```bash
npm i @kousta-ui/table
```

```bash
npm i @kousta-ui/components @kousta-ui/hooks @kousta-ui/helpers
```

| Package | What it's for |
|---------|---------------|
| [`@kousta-ui/table`](/docs/Table/DataTable/overview) | `DataTable` and the `Table` primitives |
| [`@kousta-ui/components`](/docs/Components/overview) | Buttons, modals, menus, selects, inputs, pagination |
| [`@kousta-ui/hooks`](/docs/hooks/overview) | `useDisclosure`, `useScrollLock`, `usePagination`, `useDebounceCallback` |
| [`@kousta-ui/helpers`](/docs/helpers/overview) | Nested-property read/write used by key paths like `"location.address"` |

## Import the styles

<Badge color="danger">Required</Badge> Each package ships one stylesheet. Import it **once**, anywhere in your app — without it everything renders unstyled.

```tsx
import "@kousta-ui/components/esm/index.css";
import "@kousta-ui/table/esm/index.css"; // only if you use the table
```

Peer dependencies are `react >= 17` and `react-dom >= 17`. TypeScript types ship with every package — there is no `@types/*` to install.

## Your first table

The whole API is one `headers` object: the key is the column label, the value says how the column behaves.

```tsx
import { DataTable, type THeader } from "@kousta-ui/table";

import "@kousta-ui/table/esm/index.css";
import "@kousta-ui/components/esm/index.css";

type User = {
  id: number;
  name: string;
  email: string;
  location: { city: string };
};

const users: User[] = [
  { id: 1, name: "Oussama", email: "o@example.com", location: { city: "Marrakech" } },
  { id: 2, name: "Kaoutar", email: "k@example.com", location: { city: "Rabat" } },
];

const headers: THeader<User> = {
  Name: { value: "name", sortBy: {} },
  Email: { value: "email" },
  City: { value: "location.city" },       // nested paths just work
  Initial: { exec: (row) => row.name[0] }, // or compute the cell yourself
};

export default function Users() {
  return (
    <DataTable<User>
      title="users"
      data={users}
      headers={headers}
      loading={false}
      keyExtractor={(row) => row.id}
    />
  );
}
```

That's a sortable table. Adding `pagination`, `actions.search` or a `filterBy` on a header turns on the rest — see [DataTable](/docs/Table/DataTable/overview).

## The one concept worth knowing

Nearly every table feature works two ways, and **which one you get is decided by a single prop**: whether you pass `actions.get`.

| | No `actions.get` | `actions.get` provided |
|---|---|---|
| Sorting | The table reorders `data` itself | Calls `actions.get` with `sortBy` / `direction` |
| Search | `actions.search.static: true` filters locally | Calls your handler with the query |
| Pagination | `pagination.type: "static"` slices `data` | You feed it one page at a time |
| Filtering | The table narrows `data` itself | Calls `actions.get` with the active filters |

Static is for data you already have; dynamic is for data behind an API. There is no separate mode flag — see [Sorting](/docs/Table/DataTable/Sorting) for the long version.

## Make it yours

Set defaults once for a whole tree instead of repeating props:

```tsx
import { ComponentPropsProvider } from "@kousta-ui/components";
import { TablePropsProvider } from "@kousta-ui/table";

<ComponentPropsProvider button={{ size: "md", variant: "primary" }}>
  <TablePropsProvider toggleRows={false}>
    <App />
  </TablePropsProvider>
</ComponentPropsProvider>
```

Theming is plain CSS custom properties — no theme object, no build step. Override them on `:root`:

```css
:root {
  --kui-primary-600: #2563eb;
  --kui-spacing-base: 1rem;
  --kui-rounded: 0.5; /* border-radius multiplier — components use calc(var(--kui-rounded) * 1rem) */
}
```

<Badge color="yellow">Note</Badge> `--kui-rounded` has no default, so corners are square until you set it. The full token list is in [Styles](/docs/styles/styles-and-customization).
